# SIMPLIFIED_ARCHITECTURE — A안(최소 구성) vs B안(고급)

> 작성 2026-10-25 · 시간·확률은 **추정**(테넌트에서 측정하지 않음). 기능을 지우지 않고, **A안으로 시작해 필요한 것만 B안으로 올린다.**

## 1. 두 구성

| | **A안 Minimum Viable Automation** | **B안 Advanced(기존 + 감사 수정)** |
|---|---|---|
| 목록 | ActionItems, FlowErrorLog (2개) | + DecisionLog, Holidays, MeetingIntake, ActionCandidates, TeamRoster, FactorySenders, FactoryInbox (9개) |
| 흐름 | P3A-1 플래그→할 일, P3A-2 간단 아침 메일, (선택) P3P-F3 번호 | P3P-F1~F13 (F5는 Workflows 앱 필요로 보류) |
| Office Scripts | **없음** | 6개(브리핑·리마인더·AI 가드·기한 추정·회의 준비·주간 정리) |
| 결정 기록 | 없음(할 일만) | Outlook 범주 → 결정요청·제안, 확정은 사람이 |
| AI | 없음 | Copilot 추출 → 가드 → 사람 승인 |
| 알림 | 본인 메일 1통/일 | 본인 메일(또는 Teams) 여러 종 |

## 2. 비교 (추정)

| 항목 | A안 | B안 | 근거 |
|---|---|---|---|
| 구축 시간 | **약 2시간** (목록 40분, 흐름 2개 70분, 시험 10분) | 약 10~12시간(4주 분산) | START_HERE_V2 단계별 합 |
| 주간 관리 시간 | 약 15분(완료 처리·오류 확인) | 약 30~45분(확인 요청 메일·후보 승인·오류 확인) | kpi_report `A_ADDED_MANAGEMENT`·`ADDED_MANAGEMENT` |
| 사용 편의 | 메일 플래그 + 아침 메일 하나만 기억 | 범주·회의 붙여넣기·후보 승인 등 습관 4~5개 | — |
| 확장성 | B안 흐름으로 하나씩 교체(같은 고유키, 중복 없음 — 테스트 완료) | 팀 확산은 SharePoint 라이브러리 스크립트·서비스 계정 필요 | test_audit `test_upgrade_from_mva_to_full_flow_has_no_duplicates` |
| 라이선스 | M365 포함 Power Automate 표준 커넥터 | 동일 + Copilot(회의 추출에만) | DEPENDENCY_MATRIX |
| 실패 가능 지점 | 커넥터 2개(Outlook·SharePoint), 식 246개(F3 포함) | 커넥터 6개, 스크립트 6개, 식 약 950개(F3 포함 B안 전체) | `tools/lint_flows.py` 식 개수 |
| 실패 가능성(추정) | 낮음 — Office Scripts·Run script 출력 경로(미확인 D3) 의존 없음 | 중간 — Run script 출력 경로, 스크립트 권한, 일일 실행 한도 | AUDIT_REPORT R3 |
| 연간 순절감(가정) | **약 33h** | 약 153h(+조직 결정 시 44h) | `measurement/expected_savings.csv` |

**권고:** 1주차는 A안. 2주 동안 '플래그 → 할 일 → 아침 메일' 습관이 붙고(시간기록상 아침 파악 시간이 줄면) B안 기능을 하나씩 켠다. 습관이 안 붙으면 B안을 만들어도 효과가 없다.

## 3. 간단한 브리핑에 Office Scripts가 필요한가 (재검토)
- **필요 없다(A안).** '기한 지남·임박·기한 없음' 분류와 표는 표준 액션(배열 필터링·선택·HTML 표 만들기)으로 된다(P3A-2, 테스트 완료).
- Office Scripts가 값을 하는 부분: 점수로 TOP5 고르기, 일정의 빈 시간(집중 시간), 휴무일 건너뛰기, 28KB 카드 크기 관리, 회의별 참석자 대조. 이것들이 실제로 필요하다고 느낄 때 B안 P3P-F6으로 바꾼다.

## 5. 자동 완료·후속 조치 정책 (감지가 불확실하면 사람에게 묻는다)

| 사건 | 감지 신뢰도 | 자동화가 하는 일 | 사람이 하는 일 |
|---|---|---|---|
| Outlook에서 플래그 완료 | 중(V4가 완료에도 반응하는지 미확인) | 목록은 그대로, 동기화 메모 + 본인 확인 요청(하루 1회) | 목록에서 완료 |
| 목록에서 완료 | 높음 | 완료일시 기록(F3) | — |
| 완료한 할 일 메일이 다시 플래그·변경 | 낮음(재플래그와 다른 변경 구분 불가) | 다시 열지 않음, 메모 + 확인 요청 | 필요하면 상태를 미착수로 |
| 회신 도착(회신대기 할 일) | 낮음(대화 연결 판정 미구현) | **하지 않음** — 리마인더에 계속 표시 | 회신 확인 후 완료 |
| 담당자 변경 | 높음(사람이 목록에서) | 다음 리마인더부터 새 담당자 기준(프로토타입은 본인만 발송) | — |
| 플래그 기한 변경 | 중 | 목록 기한을 사람이 안 바꿨으면 따라감, 바꿨으면 메모만 | — |
| 결정 확정 | 높음(사람이 상태 변경) | 확정일 기록, 빈 결정권자·근거·후속조치 표시 | 빈 칸 채우기 |
| 결정 번복 | 높음(사람이 '번복'으로) | 상태 기록(F4) | 대체한 결정번호 입력 |
| 같은 메일 중복 생성 | 높음(같은 고유키) | 나중 것을 '취소' + 원본 ID 메모(삭제 없음) | — |

## 6. 실제로 없어지는 일 (업무 제거 분석)

| 기존 일 | A안 | B안 | 새로 생기는 일(추가 관리) |
|---|---|---|---|
| 메일함을 훑어 할 일 찾기 | 플래그한 것만 목록에 → **찾기 제거** | 동일 + 기한 문구 자동 추정 | 플래그 누르기(건당 몇 초) |
| 아침에 무엇부터 할지 정리 | 초과·임박·기한 없음 표 → **분류 제거**, 순서는 사람이 | 점수 TOP5 + 일정·집중 시간 → **순서 정하기도 대부분 제거** | 아침 메일 읽기 |
| 진행 확인·독촉 | 본인 몫만 | 담당자별 리마인더(승인 후 타인) | 완료 처리 |
| 회의 후 결정·할 일 정리 | — | Copilot 추출 + 가드 → 붙여넣기·승인만 | 후보 승인, 제안 확정 |
| 공장 첨부 저장·정리 | — | **완전 제거**(자동 저장·대장) | 발신자 등록(1회) |
| 주간보고 초안 | — | 집계 자동, 문장 다듬기만 | 검토 |
| 오류 대응 | 오류 메일 확인 | 동일 | 월 1시간 내외(가정) |

## 7. 팀 단계로 갈 때 바뀌는 것(지금은 하지 않음)
