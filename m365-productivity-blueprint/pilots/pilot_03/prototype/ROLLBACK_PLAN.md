# ROLLBACK_PLAN — 되돌리기 계획

> 원칙: **지우지 말고 끈다.** 흐름은 '끄기(Turn off)', 목록은 그대로 두고 보기·버전 기록으로 되돌린다. 데이터 삭제는 하지 않는다.
> 모든 것은 본인 범위(내 목록·내 OneDrive·내 흐름)라서 되돌려도 다른 사람에게 영향이 없다.

## 1. 언제 되돌리나 (중단 기준)

| 신호 | 기준 | 조치 |
|---|---|---|
| 같은 메일로 할 일이 2건 이상 '미착수'로 생김 | 1건이라도 | §2-A |
| 목록 값(근거·링크·기한)이 자동화 후 비어 있음 | 1건이라도 | §2-B (P0-5 보존 패턴 실패 — T-T6) |
| 흐름이 같은 항목에 계속 실행됨 | 실행 기록에 같은 항목 10회 이상/시간 | §2-C |
| 본인이 아닌 사람에게 메일·메시지 | 1건이라도 | **즉시 모든 흐름 끄기** + 팀장 보고 |
| 아침 메일이 오지 않음 | 2영업일 연속 | §2-D |
| 순절감이 관리시간보다 작음 | 4주차 측정 | 해당 기능만 끄기(MEASUREMENT 3장 6) |

## 2. 되돌리는 방법

### A. 중복 할 일
1. Power Automate › 내 흐름 › 해당 흐름(P3A-1 또는 P3P-F1) **… › 끄기**
2. 같은 메일을 감시하는 흐름이 두 개 켜져 있는지 확인(P3A-1과 P3P-F1을 동시에 켜면 안 됨)
3. 중복분은 상태를 '취소'로(삭제 금지) → 동기화 메모에 '수동 정리' 기록
4. 원인 확인 후 하나만 켜기

### B. 값이 지워짐
1. 원인 흐름 끄기
2. 목록 › 항목 › **… › 버전 기록(Version history)** › 직전 버전 **복원**(목록 버전 기록은 LISTS_SETUP 설정으로 켜져 있어야 함)
3. 해당 흐름의 Update item 입력이 BUILD_TABLES의 '모든 열을 채운다' 지시대로인지 확인(빈 칸이 있으면 동적 값으로 채움)

### C. 반복 실행(루프)
1. 흐름 끄기
2. 트리거 조건(설정 › 트리거 조건)이 BUILD_TABLES와 똑같은지 확인 — 특히 F3·F4의 `PrevStatus`, F13의 '액션번호 있음'
3. 다시 켠 뒤 항목 1건으로 시험

### D. 아침 메일이 안 옴
1. 실행 기록 확인: 실행이 없으면 연결 만료 가능 → **데이터 › 연결**에서 Office 365 Outlook·SharePoint 연결 '수정/다시 로그인'
2. 실패면 FlowErrorLog 또는 '[P3 오류]' 메일 확인
3. B안(P3P-F6) 문제면 A안(P3A-2)을 다시 켜고 F6을 끈다(같은 목록을 읽기만 하므로 안전)

## 3. 단계별 되돌리기(B안 → A안)

| 되돌릴 단계 | 끄는 흐름 | 다시 켜는 흐름 | 데이터 |
|---|---|---|---|
| 2주차(B안 전환) | P3P-F1, F2, F4, F6, F7, F13 | P3A-1, P3A-2 | DecisionLog는 그대로 둠(읽기 전용으로 사용 가능) |
| 3주차(회의 추출) | P3P-F8, F9 | — | 후보 목록 그대로, 승인하지 않으면 아무것도 등록되지 않음 |
| 4주차(공장 자료 등) | P3P-F10, F11, F12 | — | OneDrive 저장 파일·대장 그대로(원본은 메일에 있음) |
| 전체 중단 | 모든 P3 흐름 | — | 목록은 내 목록에 남음. 필요 없으면 90일 뒤 본인이 삭제 판단 |
