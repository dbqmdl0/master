## 2. KPI와 검증 방법

| KPI | 정의 | 데이터 원천 | 수집 방법 | 목표(4주) |
|---|---|---|---|---|
| 업무시간 절감 | 위 6개 업무의 일평균 분 차이 | 시간기록 | `measurement/timelog_template.csv`에 기준선 5일 → 적용후(3~4주차) 5일 | 1장 목표의 70% 이상 |
| 자동·반자동 등록 비율 | 등록 경로 ≠ '수동'인 액션 비율 | ActionItems | CSV 내보내기 → `kpi_report.py report` | ≥ 70% |
| 액션 기한 초과율 | 미결(기한 있음) 중 기한 경과 | ActionItems | 〃 | 기준선 대비 −50% |
| 기한 내 완료율 | 완료일 ≤ 기한 | ActionItems | 〃 | ≥ 80% |
| 기한 미정 액션 | 미결 중 기한 없음 | ActionItems | 〃 | ≤ 10% |
| 결정 대기시간 | 결정요청 → 확정 중앙값(일) | DecisionLog | 〃 | 측정 시작(기준선 확보 자체가 성과) |
| AI 추천 채택률 | '추천' 후보 중 승인 | ActionCandidates | 〃 | ≥ 90%(미달 시 AI 단계 끔) |
| 흐름 안정성 | 성공 실행 비율 | Power Automate 실행 기록 + FlowErrorLog | 주 1회 확인 | ≥ 98% |

## 3. 측정 절차
1. **기준선(도입 전 5근무일):** 매일 퇴근 전 5분, `timelog_template.csv`에 업무별 소요분 기록(구분=기준선). 정례 현황회의는 Outlook 일정의 실제 시간
2. **도입(1~2주차):** 습관 형성 기간 — 측정하지 않는다(학습 비용 포함 왜곡 방지)
3. **적용후(3~4주차 중 5근무일):** 같은 양식(구분=적용후)
4. **집계:** ActionItems·DecisionLog·ActionCandidates를 각각 **내보내기 › CSV로 내보내기** → 한 폴더에 저장 → `python3 tools/kpi_report.py report <폴더> --timelog <시간기록.csv>`
   *실제 데이터 CSV는 PC에서만 다루고 이 저장소에 커밋하지 않는다.*
5. **판정:** 보고서 5장에서 '실측 확정'된 업무만 기대효과 표의 가정값을 실측값으로 교체 → `09_KPI_ROI_Model.csv` 갱신 → 팀장 보고
6. **중단 기준:** 4주차에 순절감이 유지시간(주 0.2h)보다 작으면 해당 기능을 끄고 원인(사용률·습관·도구) 기록

## 4. 해석 주의
- 시간기록은 자기 보고라 과대·과소가 있다. 같은 사람·같은 양식·같은 요일 구성으로 비교해 오차를 줄인다.
- 목록 KPI는 **입력된 것만** 센다. 자동 등록 비율이 낮으면 기한 초과율이 좋아 보여도 신뢰하지 않는다.
- AI 채택률이 높아도 사람이 수동으로 추가한 액션(누락)이 많으면 품질이 낮은 것이다 — 회의당 수동 추가 건수를 시간기록 비고에 적는다.
